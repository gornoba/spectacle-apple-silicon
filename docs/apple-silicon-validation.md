# Spectacle Apple Silicon ver 1.0 검증 내역

## 버전과 범위

- 프로젝트 버전: **Spectacle Apple Silicon ver 1.0**, 앱 표시 버전 `1.0`, 빌드 `1`.
- 원본 기준: [Spectacle master e75c341](https://github.com/eczarny/spectacle/commit/e75c341).
- 아키텍처: `arm64` 전용, macOS 배포 하한 `13.0`.
- 앱 식별자: `com.divisiblebyzero.Spectacle`. 기존 단축키 JSON과 환경설정 형식을 유지합니다.
- 검증 환경: Apple M2, macOS 26.6.2, Xcode 26.6, macOS SDK 26.5.
- 이번 1.0 준비에서 바뀐 실행 관련 항목은 버전·빌드 번호와 라이선스 패키징입니다. 이전 개발 검증본 1.3.0의 기능 코드는 유지합니다. 설치된 앱은 이번 작업에서 교체하지 않았습니다.

## 버전 1.0 자동 검사

| 항목 | 결과 | 근거 |
|---|---|---|
| Release 빌드 | 통과 | arm64 · macOS 13 대상, 컴파일 경고를 오류로 처리하는 설정 유지 |
| 앱·ZIP 버전 | 통과 | 압축 해제된 Info.plist의 1.0 / 빌드 1 확인 |
| 모든 Mach-O 아키텍처 | 통과 | `file`, `lipo`; 포함 실행 파일은 본체 하나이며 arm64 |
| 링크 라이브러리 | 통과 | `otool -L`; 시스템 라이브러리만 연결 |
| 최소 macOS | 통과 | Info.plist와 `vtool`의 13.0 일치 |
| Sparkle·업데이트 피드 | 통과 | 라이브러리·설정·메뉴 연결 제거, 패키지 검사 |
| 서명·실행 권한 | 통과 | 추출 앱의 strict ad-hoc 서명과 실행 권한 확인 |
| ZIP 구조·라이선스 | 통과 | 최상위 Spectacle.app 하나, 내부에 원본 LICENSE.md 전문 포함 |
| XCTest | 통과 | 108개, 실패 0개: 기존 99 + 로그인 상태 7 + 아카이브 호환 1 + 그리기 회귀 1 |

현재 Xcode의 XCTest 라이브러리는 macOS 14 대상으로 만들어져 테스트 링크에서 최소 OS 차이 경고 2개가 발생합니다. 경고를 숨기지 않았으며 실제 실행 환경은 macOS 26.6.2입니다. 배포 앱에는 XCTest가 포함되지 않습니다. macOS 13에서 테스트하려면 해당 OS와 호환되는 Xcode/XCTest 환경이 필요합니다.

## 이전 개발 검증본에서 확인한 실제 동작

아래는 같은 기능 코드를 사용하는 **1.3.0 개발 검증본**의 실제 결과입니다. 1.0 패키지 자체를 새로 실행한 결과와 구분합니다.

| 항목 | 결과 | 관찰 |
|---|---|---|
| 실제 프로세스 | 통과 | 정식 설치 경로에서 ARM64 실행, 실행 파일 경로·PID 확인 |
| 절반·모서리·가운데·최대화 | 통과 | 사용자의 실제 키보드 입력 |
| 1/2·2/3·1/3 순환, 확대·축소, 가로·세로 3분할 | 통과 | 사용자의 실제 키보드 입력 |
| 다중 모니터·Undo·Redo | 통과 | 내장 2배율, 외장 1배율 가로·세로 화면과 메뉴 확인 |
| 설정 화면 | 통과 | 그리기 회귀 수정 후 스크린샷·사용자 확인 |
| 기존 설정 보존 | 통과 | 18개 단축키 항목과 기존 환경설정 값의 의미 비교 |
| 접근성 | 통과 | 사용자가 새 서명의 설치 앱을 재승인한 뒤 창 조작 확인 |
| 로그인 등록 | 통과 | 사용자 승인 후 재등록, 활성·허용 상태의 항목 1개와 `/Applications/Spectacle.app` 경로 확인 |

전역 단축키에 자동화 입력이 전달되지 않는 현상은 실제 키보드 확인과 구분했습니다. 기존 사용자 지정 단축키 10개와 Undo·Redo 미할당 상태를 보존했으며, 메뉴로 Undo·Redo를 검사했습니다.

초기 `AXFocusedWindow -25211` 오류는 SDK의 `kAXErrorAPIDisabled`와 일치했습니다. 단축키 핸들러는 호출됐지만 접근성 승인이 새 서명에 적용되지 않은 상태였고, 사용자의 재승인으로 해결됐습니다.

설정 화면의 큰 흰 원은 입력칸이 `drawRect:`의 dirtyRect를 자신의 크기로 사용해 발생했습니다. 최신 NSView의 기본 clipping 동작을 확인하고 `self.bounds`와 명시적 그리기 제한으로 수정했습니다. 수정 전 입력칸 밖 픽셀 alpha 약 0.91로 실패를 재현했고, 수정 후 회귀 테스트가 통과했습니다.

로그인 체크박스가 켜져 있어도 시스템 등록이 임시 후보 경로를 가리킬 수 있었습니다. 실제 BTM 기록을 검사한 뒤 사용자 승인으로 정식 설치 앱을 다시 등록했습니다. 시험용 후보 실행 후에는 등록 경로도 확인해야 합니다.

## 남은 미검증

- **1.0 패키지 자체의 새 설치·실제 실행:** 이번 작업은 새 릴리스 패키지 준비이며 설치 앱을 바꾸지 않았습니다.
- **실제 로그인 후 자동 실행:** 사용자가 로그아웃·재로그인을 보류했습니다. 등록 확인을 실제 실행 확인으로 보고하지 않습니다.
- **macOS 13 실기기 실행**, 다른 Apple Silicon 칩 및 다른 사용자의 Mac에서의 다운로드 설치.
- **Developer ID 서명·Apple 공증:** 미적용. ad-hoc 서명 ZIP으로 보안 경고가 발생할 수 있습니다.

현재 macOS에서의 측정 결과를 미래 macOS의 동작 보장으로 해석하지 않습니다.

## 재검증·복구 절차

1. 기존 앱과 Shortcuts.json·환경설정을 백업합니다. 자동 백업 스크립트는 `scripts/backup-installed.py`이며 결과는 공개하지 않는 `build/backups/`에 저장됩니다.
2. 사용자 확인 후 기존 앱을 정상 종료하고 후보 하나만 실행합니다. 정확한 실행 경로와 실제 ARM64 실행을 확인합니다.
3. 새 서명의 접근성 승인 후 빈 테스트 창에서 위 기능을 실제 키보드·메뉴로 확인합니다.
4. 설치 앱 교체는 별도 확인 후 진행하고, 로그인 등록이 정식 설치 경로를 가리키는지 검사합니다. 기존·중복 항목은 확인 없이 삭제하지 않습니다.
5. 실제 재로그인 검증은 저장 중인 작업을 정리하고 사용자 확인 후 진행합니다.
6. 실패하면 두 앱을 모두 종료한 상태에서 원본 앱·설정을 복원합니다. 환경설정 캐시가 파일 복원을 덮어쓰지 않도록 macOS 환경설정 API나 사용자 절차를 따릅니다. 로그인·접근성은 복원한 앱 기준으로 재확인하며 TCC 데이터베이스를 직접 수정하지 않습니다.
